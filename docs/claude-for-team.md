# Как работать над проектом через Claude

Материал для занятия с командой. Его можно показывать как есть или сделать по нему слайды.

## Зачем и где граница

Claude помогает быстрее разобраться в незнакомом коде, написать черновик, найти ошибку, составить тесты. Но по правилам ИТМО об использовании ИИ:
- **каждый отвечает за свою работу сам** и должен понимать, уметь объяснить и защитить любую её часть, включая сделанную с ИИ;
- **использование ИИ декларируется**: для чего, какие запросы, какие решения приняли вы;
- **нельзя отправлять во внешние сервисы чужие закрытые данные** (пароли, личные данные, чужие неопубликованные работы).

На защите вопрос может прийти любому участнику про любую часть проекта. «Это написал ИИ» — не ответ.

## Инструменты

- **Claude Code** — работает прямо в репозитории: читает файлы, предлагает и вносит правки, запускает команды и тесты. Установка: https://code.claude.com/docs/en/quickstart
- **Claude в браузере или приложении** — для вопросов, объяснений и текстов, если не нужен доступ к коду.
- Claude Code нужен платный тариф Claude (Pro, Max, Team, Enterprise) или аккаунт Console; на бесплатном тарифе его нет (https://code.claude.com/docs/en/setup). У кого Claude Code нет — работает в браузере и вручную с Git, процесс тот же.
- В Android Studio есть плагин Claude Code [Beta]: правки открываются во встроенном окне сравнения (https://code.claude.com/docs/en/jetbrains).

В корне репозитория лежит `CLAUDE.md`: Claude Code читает его в начале работы и сразу знает, что за проект, какие требования и правила. Обновлять `CLAUDE.md` может только руководитель (через PR). Подробнее о файле: https://code.claude.com/docs/en/memory

## Порядок работы над задачей

1. Возьмите свою задачу на доске, переведите в «В работе».
2. Создайте ветку: в Claude Code — `/start-task 12`; без него — в issue справа «Development → Create a branch», имя `feature/12-card-editor`.
3. Запустите Claude Code в папке репозитория и дайте ему задачу целиком: номер issue, что сделать, критерий готовности.
4. Для задачи больше пары файлов попросите **сначала план**. Прочитайте план, задайте вопросы, только потом соглашайтесь на правки. О режиме планирования: https://code.claude.com/docs/en/common-workflows
5. После правок попросите объяснить, что изменено и почему. Чего не поняли — переспросите, пока не поймёте.
6. Проверьте сами: соберите, запустите, пройдите сценарий, прогоните тесты.
7. Откройте PR по шаблону (`/finish-task` поможет), заполните раздел «Использование ИИ» сами. Переведите карточку в «На ревью».
8. Перед защитой — `/explain-my-work`: Claude объяснит сделанное и задаст контрольные вопросы.

## Примеры запросов по ролям

**Android (экраны):**
> Прочитай CLAUDE.md и docs/tz.md. Задача #12: экран редактирования карточки по макету (ссылка). Сначала предложи план: какие файлы создашь, какие состояния у экрана. Код пока не пиши.

**Алгоритм:**
> Объясни, как работает FSRS, на примере одной карточки и трёх ответов. Потом предложи интерфейс модуля `core-srs` без зависимостей от Android и список юнит-тестов к нему.

**Backend:**
> Нужен сервер, который отдаёт список наборов и содержимое набора в JSON по формату из docs/product.md. Предложи минимальный вариант, который можно развернуть бесплатно на время защиты, и опиши API.

**Контент:**
> Проверь, что файл content/basic-words.json соответствует формату из docs/product.md: обязательные поля, уникальные id, нет пустых переводов. Переводы не меняй — только укажи, где проблемы со структурой.

Переводы и правила языка Claude не проверяет надёжно. Источник истины — словари и учебники, которые контент-лид указывает в наборе.

**Тестирование:**
> На основе раздела 6 docs/tz.md составь чек-лист ручной проверки: по одному пункту на каждое требование, с шагами и ожидаемым результатом.

**Дизайн:** Figma — отдельный инструмент. Claude можно попросить разобрать сценарий пользователя или проверить, все ли состояния экрана учтены (пустой список, ошибка сети, загрузка).

## Как проверять ответы ИИ

- Код — запуском и тестами, а не на глаз.
- Факты и формулы (например, FSRS) — по первоисточнику.
- Языковой контент — по словарям, минимум по двум источникам.
- Если ответ звучит уверенно, но вы не можете его проверить, считайте его непроверенным.

## Декларация использования ИИ

Раздел в каждом PR (шаблон уже в `.github/pull_request_template.md`):
- для чего использовали Claude (план, код, тесты, объяснение, текст);
- ключевые запросы — коротко, своими словами или цитатой;
- что вы проверили и изменили сами;
- что решили иначе, чем предлагал ИИ, и почему.

## Типичные ошибки

- Принять большой кусок кода, не прочитав его. На ревью попросят объяснить каждую часть.
- Просить «сделай всё приложение». Задачи должны быть маленькими, по одной карточке доски.
- Давать Claude токены и пароли в чате или коммитить их в репозиторий.
- Менять требования ТЗ «потому что так проще». Вопросы по ТЗ — к руководителю.

App: 70 debug + 70 release unit tests; core-srs: 22; инструментальные: **45, 0 падений, 2 пропуска**. Точное число взято из XML: в текстовом выводе UTP счётчик завершённых тестов включает повторные события пропусков.

- Сетевой и долгий тесты включаются отдельно: `adb shell am instrument -w -e class ru.itmo.tuman.AcceptanceSmokeTest -e qaNetwork true -e qaReminder true ru.itmo.tuman.test/androidx.test.runner.AndroidJUnitRunner`. Сначала установить app-debug.apk и app-debug-androidTest.apk. Их отсутствие в обычном прогоне — осознанный пропуск, не успех.
- Настоящий WorkManager проверен отдельно: выбранное время **01:32**, расписание включено в 01:30:07.323, уведомление опубликовано в **01:32:00.145** (время устройства, MSK). Нажатие воспроизведено через PendingIntent, приложение возобновилось; затем напоминание отключено, unique work имеет состояние **CANCELLED**. Это один успешный прогон, не гарантия точности WorkManager на всех устройствах.
- **Дополнительный офлайн-прогон подтверждён:** режим полёта включён через настройки Android, `dumpsys connectivity` показывает `Active default network: none`. После перезапуска приложения скачанный набор из 9 букв полностью повторён всеми 4 оценками; прогресс открыт (144 XP, 19/20 с учётом предыдущих ответов); каталог показал «Нет интернета». Снимки offline-01…05 и offline-acceptance.json приложены. Команды `svc disable` первоначально не обеспечили нужную фикстуру; этот пропуск заменён проверкой через настройки. Сеть восстановлена; техническая ошибка завершающей svc-команды описана в журнале, последующая независимая проверка подтверждает активный Wi-Fi.
